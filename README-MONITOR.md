# Моніторинг офіційних документів Гладковицької громади

Джерело: https://gld-tg.gov.ua/docs/

## Що робить

- Перевіряє каталог документів один раз на добу.
- Публічна сторінка дає змогу шукати документи, фільтрувати їх за типом, відкривати офіційні картки та переходити до кожного вкладення на офіційному сайті.
- Окремо показує підтверджено зниклі документи й журнал нових, змінених та видалених матеріалів.
- Виявляє нові, змінені та підтверджено зниклі документи й вкладення.
- Перший запуск створює базовий знімок і не оголошує старий архів новим.
- Документ вважається зниклим лише після двох послідовних перевірок.
- Порожній або підозріло скорочений каталог не перезаписує справний стан.
- Звичайний запуск повторно читає тільки нові, змінені й нещодавні картки.
- Раз на 7 днів та при ручному запуску виконується повна звірка всіх карток.
- GitHub Pages розгортається явно з того самого workflow, тому сторінка оновлюється навіть тоді, коли немає коміту.

## Файли

- `monitor.py` — монітор;
- `index.html` — головна публічна сторінка;
- `status.html` — перенаправлення на головну сторінку для сумісності;
- `state.json` — останній стан;
- `changes.json` — історія суттєвих подій;
- `config.json` — параметри безпеки та частоти;
- `.github/workflows/monitor.yml` — перевірка і публікація GitHub Pages.

## Встановлення

1. Створіть окремий публічний репозиторій, рекомендована назва — `gladkovychi-document-monitor`.
2. Завантажте **вміст пакета в корінь репозиторію**. Файл workflow має опинитися саме за шляхом `.github/workflows/monitor.yml`.
3. Відкрийте `Settings → Pages` і виберіть `Source: GitHub Actions`.
4. Відкрийте `Actions → Monitor official documents → Run workflow`.
5. Перший ручний запуск виконає повну базову звірку. Через велику кількість документів він може тривати кілька хвилин.

Публічна адреса після успішного розгортання:

`https://14widow14-tech.github.io/gladkovychi-document-monitor/`

## Розклад

`17 3 * * *` — один раз на добу, приблизно о 03:17 UTC (06:17 за київським літнім часом). GitHub може трохи затримати запланований запуск.

## Захисні механізми

- Якщо не розпізнано жодної картки, запуск завершується помилкою без перезапису стану.
- Якщо кількість карток падає нижче 85% попереднього стану, запуск завершується без масового видалення.
- Якщо кількість сторінок перевищує захисний ліміт, потрібно спочатку перевірити сайт і збільшити `max_pages` вручну.
- JSON записується через тимчасовий файл і атомарну заміну.
- Пошкоджений JSON не скидається мовчки, а зупиняє workflow.

## Вартість і доступ

Firecrawl, зовнішні API-ключі та платні кредити не потрібні. Для публічного репозиторію використовуються GitHub Actions і GitHub Pages. Дані `state.json` та `changes.json` є публічними разом із сайтом.
